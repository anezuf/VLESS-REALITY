# Гайд по настройке панели 3x-ui

## Reset (при необходимости)

```bash
ssh-keygen -R <ip-server>
```

---

## 1. Системное обновление

```bash
sudo apt update && sudo apt upgrade -y
```

---

## 2. Установка 3x-ui. [Скрипт x-ui pro](https://github.com/mozaroc/x-ui-pro)

```bash
bash <(wget -qO- https://github.com/mozaroc/x-ui-pro/raw/master/x-ui-pro.sh) -install yes -panel 1 -ONLY_CF_IP_ALLOW no
```

## 3. Настройка SNI в подключениях

В панели 3x-ui, в настройках подключения (inbound), прописать SNI — это домен, под который маскируется трафик. Используются российские домены, чтобы трафик выглядел легитимным для РКН:

- `api-maps.yandex.ru`
- `www.vk.com`
- `gp.x5.ru`
- `ozon.ru`

Можно использовать любой другой популярный российский домен. Главное — чтобы он был достаточно крупным и не вызывал подозрений.

---

## 4. Включение сниффинга

В настройках inbound включить **Sniffing** и поставить галочки на:

- [x] http
- [x] tls
- [x] quic
- [ ] FAKEDNS

Обязательно включить опцию **`Route Only`**.

Сниффинг нужен для того, чтобы xray мог определить протокол и домен назначения прямо из трафика — без его расшифровки. Это позволяет маршрутизатору понять, куда идёт пакет, и применить правила маршрутизации: например, заблокировать трафик на российские домены или направить его в нужный туннель. Опция `Route Only` гарантирует, что сниффинг используется исключительно для маршрутизации, а не для изменения самого трафика.

---

## 5. Стратегия разрешения DNS

В панели: **Настройки Xray → Основные настройки → Настройка маршрутизации доменов**

Измените значение с **`AsIs`** на **`IPIfNonMatch`**.

Это означает, что Xray сначала пытается применить правила маршрутизации по домену. Если ни одно доменное правило не подошло, Xray резолвит домен в IP-адрес и повторно проверяет маршрутизацию уже по IP-правилам.

Такой режим удобен, когда основная логика маршрутизации построена по доменам, а проверка по IP нужна только как резервный этап.

---

## 6. Базовое соединение — Warp

В панели: **Настройки Xray → Базовые соединения**

Установить **Warp** в качестве базового исходящего соединения. Весь трафик, не попавший под другие правила, будет уходить через Warp.

---

### 7. Маршрутизация

### Архитектура маршрутизации (Routing Table)

Правила в Xray обрабатываются **строго сверху вниз**.  
Сначала применяются блокирующие и служебные правила, затем оставшийся разрешенный трафик направляется в нужный outbound.

Ниже приведена рекомендуемая таблица маршрутизации для данной конфигурации:

| № | Что проверяем | Значение | Исходящий тег | Назначение |
|---:|---|---|---|---|
| **1** | IP | `geoip:ru` | `blocked` | Блокировка трафика к IP-адресам, географически относящимся к РФ |
| **2** | Domain | `domain:ru`, `domain:su`, `domain:xn--p1ai`, `geosite:category-ru`, `geosite:category-ads-all` | `blocked` | Блокировка российских доменов, связанных доменных списков, а также рекламных и трекинговых доменов |
| **3** | Network + Port | `UDP` + `443` | `blocked` | Блокировка QUIC/HTTP/3 и принудительный переход на TCP |
| **4** | Inbound Tag | `api` | `api` | Обеспечение корректной работы API и панели управления |
| **5** | IP | `geoip:private` | `blocked` | Блокировка доступа к приватным IP-адресам через сервер |
| **6** | Protocol | `bittorrent` | `blocked` | Блокировка BitTorrent/P2P-трафика |
| **7** | User / Email | `first` | `warp` | Отправка разрешенного трафика клиента через Cloudflare WARP |

> Если ни одно правило не совпадет, Xray отправит трафик в outbound по умолчанию.  
> Поэтому при добавлении новых клиентов рекомендуется явно контролировать финальное правило маршрутизации.

---

### Логика правил

- **Правила 1–2** блокируют нежелательные направления до отправки трафика в основной outbound: IP-адреса РФ, российские доменные зоны, а также рекламные и трекинговые домены.
- **Правило 3** блокирует `UDP:443`, чтобы браузеры и приложения не использовали QUIC/HTTP/3 и переключались на обычный TCP.
- **Правило 4** — служебное. Оно нужно для корректной связи панели управления с API Xray.
- **Правило 5** запрещает доступ к приватным IP-адресам через сервер.
- **Правило 6** блокирует BitTorrent/P2P-трафик, чтобы снизить риск жалоб со стороны хостинг-провайдера.
- **Правило 7** отправляет оставшийся разрешенный трафик клиента `first` через outbound `warp`.

---

### Сводка фильтров

**Заблокированные IP-адреса:** `geoip:ru`, `geoip:private`  
**Заблокированные домены и базы:** `domain:ru`, `domain:su`, `domain:xn--p1ai`, `geosite:category-ru`, `geosite:category-ads-all`

> Примечание: правило `geosite:category-ru` зависит от используемой geosite-базы.  
> Если в вашей сборке такой категории нет, оставьте только явные домены (`domain:ru`, `domain:su`, `domain:xn--p1ai`) и другие доступные списки.
